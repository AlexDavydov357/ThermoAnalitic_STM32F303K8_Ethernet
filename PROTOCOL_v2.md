# Протокол контроллера ламп и заслонки, прошивка 2.0

Это список изменений для программы MobiTherm (`utils/locoterm_eth.py`). Связь та же: USART1 115200 8N1 через USR-TCP232-T2. Каждая команда и каждый ответ заканчиваются `;`.

## Команды

| Команда | Ответ | Что изменилось |
|---|---|---|
| `LED 0;` / `LED 1;` | `LED n;` | `LED 1` теперь действительно включает LED1 на плате. При `LED 0` светодиод, как раньше, горит только во время работы мотора. |
| `SHUT 0;` | `SHUT_0 SHUT_OPENNING;`, потом `MOTOR_DONE_OPEN;` или `MOTOR_TIMEOUT;` | Без изменений. |
| `SHUT 1;` | `SHUT_1 SHUT_CLOSING;`, потом `MOTOR_DONE_CLOSE;` или `MOTOR_TIMEOUT;` | Без изменений. |
| `SHUT 2;` | `SHUT_2 SHUTTER_STOPPED;` | Без изменений, мгновенный стоп. |
| `SHUT 0/1;` при неисправных концевиках | `SENSOR_FAULT;` | **Новое.** Движение не начинается. |
| `TIM n;` | `TIM n;` | Ограничения сверху нет, как и раньше. |
| `FLASH 1;` | `FLASH 1;`, сразу `COUNTD n;`, затем раз в секунду `COUNTD n-1;` … `COUNTD 1;`, в конце `FLASH 0;` | **Изменено:** появился ответ `FLASH 1;` до первого `COUNTD`. |
| `FLASH 1;`, если лампы уже горят или время 0 | `FLASH_BUSY_OR_TIME_ZERO;` | Без изменений. |
| `FLASH 0;`, если лампы горят | `FLASH_FORCEOFF;` | **Изменено:** было `IFLASH_FORCEOFF;`. |
| `FLASH 0;`, если лампы не горят | `FLASH 0;` | **Изменено:** было `FLASH_BUSY_OR_TIME_ZERO;`. |
| `STATUS;` | `STATUS <заслонка> LAMP <0/1> <секунд осталось>;` | **Изменено**, см. ниже. |
| `VERSION;` | `VERSION 2.0;` | **Новое.** |
| Неизвестная команда, команда без нужного числа, команда длиннее 32 символов | `UNKNOWN_COMMAND;` | **Изменено:** раньше на это часто не было ответа. |
| Пустая команда `;` | ответа нет | Как раньше. Ваш `SYNC` после подключения работает без изменений. |

Состояние заслонки в `STATUS`:

| Значение | Когда |
|---|---|
| `OPENED` | стоит на концевике «открыто» |
| `CLOSED` | стоит на концевике «закрыто» |
| `BETWEEN` | стоит между концевиками (раньше в этом случае приходило `STATUS STOPPED`) |
| `OPENING` / `CLOSING` | едет (раньше во время движения тоже приходило `STATUS STOPPED`) |
| `FAULT` | оба концевика активны одновременно |

Примеры: `STATUS CLOSED LAMP 0 0;`, `STATUS BETWEEN LAMP 1 7;`.

## Сообщения, которые контроллер шлёт сам

| Сообщение | Когда |
|---|---|
| `BOOT <причина> VERSION 2.0;` | **Новое.** После каждого включения или перезагрузки. Причина: `POWER`, `PIN` (кнопка сброса), `IWDG` (сторожевой таймер, то есть прошивка зависла), `SOFT` (программный сброс после аварии), `OTHER`. |
| `SENSOR_FAULT;` | **Новое.** Оба концевика стали активны одновременно, мотор остановлен. |
| `COUNTD n;`, `FLASH 0;` | Как раньше, во время и в конце нагрева. |
| `MOTOR_DONE_OPEN;`, `MOTOR_DONE_CLOSE;`, `MOTOR_TIMEOUT;` | Как раньше. |
| `MOTOR_DONE_STOP;`, `MOTOR_STOPPED;` | **Больше не отправляются** (в старой прошивке они тоже фактически не приходили). |

## Что поправить в клиенте

1. `ANSWER_TEXT`: добавить `SENSOR_FAULT`, `VERSION`, `BOOT`, а `STATUS` разбирать по словам (заслонка, лампа, остаток), а не сравнивать строку целиком.
2. `_REPLY_PREFIX['FLASH 1']` уже содержит `FLASH 1`, теперь он приходит первым. `_REPLY_PREFIX['SHUT']` нужно дополнить `SENSOR_FAULT`.
3. По `STATUS ... LAMP 1 n` после переподключения можно восстановить состояние лампы и отсчёта.
4. По `BOOT IWDG` или `BOOT SOFT` стоит показать оператору предупреждение: контроллер перезагрузился сам.
5. Сообщения теперь не теряются и не склеиваются внутри контроллера: ответы уходят по очереди целиком. Разбор потока по `;` в клиенте остаётся нужным, потому что T2 может склеить два сообщения в один TCP-пакет.
